# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

BrokerPorez is a Laravel 13 (PHP ^8.3) app for computing Serbian capital-gains tax on brokerage activity. Users import their broker's CSV export of transactions (columns like `Action`, `Time (UTC)`, `No. of shares`, `Price / share`, `Withholding tax`, `Charge amount`). Each transaction is converted to RSD at the official NBS middle exchange rate for its date. Sells are matched against buy lots in FIFO order, and the result feeds the PPDG-3R tax return.

Implemented: auth (registration, login, 6-digit email verification), Trading 212 CSV import, a CSV import wizard for any other broker (IBKR is listed as "uskoro"), NBS rate lookup, the FIFO ledger, a tabbed dashboard (Pregled / Kapitalna dobit / Dividende / Uvoz) and PDF export of the PPDG-3R and PP OPO tax forms. The tax logic is a port of the user's spreadsheet `trading212_invest_porezi.ods` (sheets "Kapitalna Dobit" and "Dividende", StarBasic macro `IZRACUNAJ_PORESKU_OSNOVICU`); `tests/Fixtures/excel_*.csv` are its rows and the unit tests must keep reproducing them. Domain identifiers, routes, UI text and comments are in Serbian (Latin); the PDF forms are in Cyrillic like the official ones. Keep that convention.

vendor/bin/pint --test                      # check formatting only

**CI:** `.github/workflows/deploy.yml` runs on every push to `main`: job `test` (PHP 8.4 with `bcmath`, `pdo_mysql`, `mysqli`, a `mariadb:10.11` service on port 13306, `composer install`, `npm ci`, `npm run typecheck`, `npm run build`, `php artisan test`; no `.env` is created) must pass before job `deploy` (SSH to the server: `git reset --hard origin/main`, `composer install --no-dev`, `npm run build`, cache rebuild, `chown -R www-data:www-data storage bootstrap/cache`, PHP-FPM reload; it does **not** run `migrate`, `sql/` files are applied by hand) starts; a failure mails the owner and production stays on the previous version. Keep the suite green and network-free (use `Http::fake()`), and add any new PHP extension the tests need to that job.

**Node ≥ 20.19 is required** (Vite 8, TypeScript 7 native binaries). Run `npm install` under that Node version; installing under an older Node silently skips the platform-specific optional packages and `vite`/`tsc` then fail.

## Database: read this before touching data code

- **The schema is raw SQL, not migrations**, applied by hand to MariaDB (`broker_porez`), in the order of **`sql/redosled.txt`** (the single source: the test DB is built from it, and `tests/Unit/RedosledSqlTest` fails if a `.sql` file is neither listed nor marked `!` as not applied; new files go at its end): `sql/broker_proezi_create_tables.sql` (domain), `sql/auth/korisnici_verifikacija.sql` (verification columns + `verifikacioni_kodovi`), `sql/auth/reset_lozinke.sql` (`tokeni_reset_lozinke`), `sql/auth/google_oauth.sql` (nullable unique `korisnici.google_id`), `sql/porezi/porezi_dopune.sql` (`transakcije.kurs` nullable, `kurs_porez`, `jedinstveni_kljuc` dedupe key, `poreski_profil`), `sql/porezi/poreski_obaveznik.sql` (renames it to `poreski_obaveznik`, turns `prebivaliste_sifra` into free-text `prebivaliste` and adds the PPDG-3R Deo 2 fields 2.1–2.10), `sql/porezi/opstina_prebivalista.sql` (`poreski_obaveznik.opstina_sifra`, the 3-digit municipality code for PP OPO 2.4), `sql/porezi/tekuci_racun_pasos.sql` (`poreski_obaveznik.tekuci_racun` CHAR(18) for PP OPO 3.2 and optional `broj_pasosa` for PP OPO 2.9), `sql/uvoz/izvori_uvoza.sql` (`transakcije.tip` + `transakcije.izvor`, backfilled from `tip_akcije`, and `sabloni_uvoza`), `sql/pravno/privatnost.sql` (`korisnici.uslovi_prihvaceni_at` / `uslovi_verzija`, the encrypted `poreski_obaveznik` columns widened to TEXT, and the anonymous `obrisani_nalozi`; run `php artisan obaveznik:sifruj` once afterwards), `sql/pravno/obavestenje_uslova.sql` (`korisnici.uslovi_obavesten_verzija`), `sql/podrska/podrska.sql` (`korisnici.is_insajder`, `poruke_podrske`, `prilozi_poruka_podrske`), `sql/podrska/zadovoljstvo.sql` (`korisnici.zadovoljstvo_od`, `ocene_zadovoljstva`), `sql/baza/vremenska_zona_utc.sql` (one-off: shifts the TIMESTAMP values Laravel wrote while the DB session was in the server's zone; run once together with the `timezone` setting below, it refuses a second run), `sql/session/laravel_session_table_create.sql`, `sql/cache/laravel_cache_table_create.sql`, `sql/baza/ukloni_stock_tabele.sql` (drops `users`, `password_reset_tokens`, `migrations` left by an old `migrate --force` in the deploy script). `database/migrations/` holds only the stock Laravel tables and is not run against MariaDB. New tables go in a new `sql/` file, not a migration.
- `.env` uses the MariaDB server through Laravel's `mysql` driver (`broker_porez`), with `SESSION_DRIVER`, `CACHE_STORE` and `QUEUE_CONNECTION` all set to `database`. **Tests run on MariaDB 10.11 with the real schema**, never on SQLite: `phpunit.xml` points at `broker_porez_test` on 127.0.0.1:13306 (the container from `docker/test/testovi.sh`, or the CI service) with array cache/session/mail and a test-only `APP_KEY`; `.env.testing` (no secrets) replaces `.env` so tests never read local or production credentials. `Tests\Baza\PripremaBaze` drops and rebuilds that database from `sql/redosled.txt` once per run, before the first test using `Tests\Feature\Concerns\TestBaza` (`DatabaseTransactions`, so every test is rolled back; plus `spremanKorisnik()`). It refuses a database not named `*_test`, `APP_ENV` other than `testing`, and any server that has a `broker_porez` database (local server, production through an SSH tunnel; port 3307 locally is such a tunnel). Consequences: foreign keys, `DECIMAL` as strings, `utf8mb4_general_ci` (search ignores case and č/c) and time zones behave as in production; auto-increment ids are not reset between tests, so never hard-code ids; DDL commits the transaction, so a test that needs its own table uses `$tabela->temporary()` (see `TabelaPretragaTest`).
- **Time zones:** the app (`app.timezone`) and the DB session are both UTC: `config/database.php` sets `'timezone' => '+00:00'` on the `mysql`/`mariadb` connections, so `TIMESTAMP` columns and `DEFAULT CURRENT_TIMESTAMP` agree with `now()` whatever the server's zone is. Hand-written SQL that writes times must start with `SET time_zone = '+00:00';` (the `mysql` CLI otherwise uses the server zone, e.g. CET locally). `transakcije.vreme_utc` is `DATETIME` and holds UTC.
- The cache table matters: `RateLimiter` (login throttling, code resend) uses `CACHE_STORE=database`.
- Domain tables use `kreirano_at` and no `updated_at`. Eloquent models for them need custom timestamp handling (e.g. `const CREATED_AT = 'kreirano_at'; const UPDATED_AT = null;`) and explicit `$table` names, because Serbian plurals don't follow Laravel's inflection.

### Domain model (FIFO tax ledger)

- `imovina`: the global asset registry, keyed by **ISIN** (unique). `simbol` stores the last-seen ticker, since tickers can change while ISINs don't.
- `kursevi`: the NBS middle rate per (`datum`, `valuta`), unique on that pair.
- `transakcije`: the raw ledger of CSV rows, scoped by `korisnik_id`. `tip_akcije` holds the broker's raw action text ('Market buy', 'KUPI', …) for display only; `tip` (`TipTransakcije`: KUPOVINA/PRODAJA/DIVIDENDA/DEPOZIT/OSTALO) is what FIFO, reports and tables filter on, and `izvor` (`IzvorUvoza`: TRADING212/IBKR/RUCNI) records the import source. `imovina_id` is NULL for deposits and fees. Each money field carries its own currency column, and `kurs` stores the NBS rate applied.
- `poreski_lotovi`: one lot per buy transaction. `preostala_kolicina` is decremented as FIFO consumes the lot.
- `alokacije_lotova_prodaje`: links a sell transaction to the lots it consumed. It records `iskoriscena_kolicina`, which supports fractional shares, and `nabavna_vrednost_rsd`, the proportional cost basis in RSD that PPDG-3R needs.
- `sabloni_uvoza`: per-user saved mappings of the CSV wizard (`podesavanja` JSON = `PodesavanjaUvoza::uNiz()`), unique on (`korisnik_id`, `naziv`).
- Every per-user table carries `korisnik_id` (cascade delete) for multi-user isolation. Always scope queries by user.
- Monetary and quantity columns are `DECIMAL(28,10)` and rates are `DECIMAL(20,10)`. Don't do tax math in PHP floats. Use decimal-safe arithmetic (bcmath, or a decimal cast).

## Tax pipeline

Import → rates → FIFO → reports → forms. Each step lives in `app/Services/`:

1. Every source implements `Uvoz/ParserIzvoda` and yields broker-neutral `UvezeniRed` (with `tip` and `izvor`); `Uvoz/UvozService::uvezi($korisnik, $parser, [putanja => naziv])` does dedupe, the `imovina` upsert, the insert and the rate fetch. `Uvoz/Trading212CsvParser` maps T212 columns **by header name** (exports differ: `Time` vs `Time (UTC)`, `+00:00` suffix, optional ID/Notes/Result/fee columns). Times are UTC; the NBS rate date is the **Europe/Belgrade** date. `jedinstveni_kljuc` is a content hash (not the broker ID, which dividends lack), so re-importing overlapping exports is a no-op. `Uvoz/Rucni/*` is the wizard for any other broker (`UvozRucniController`, routes `uvoz.rucni.*`, steps format → kolone → akcije → pregled): the upload waits in `storage/app/private/uvoz/{uuid}.csv` (`CarobnjakUvoza`, path only from the session), `CsvCitac` reads raw rows, `RucniCsvParser` applies a `PodesavanjaUvoza` (separator, encoding, header row, number/date format, time zone, column → field or constant, action value → `TipTransakcije`). Columns are stored by header name. A dividend with only an amount is imported as 1 × net amount, because the dividend calculation is quantity × net per share.
2. `Kursevi/NbsKursService` reads `kursevi` (middle rate by NBS *date of application*, per 1 unit; GBX = GBP/100) and fetches missing dates from `config('porezi.kurs_api_url')` (`/rates/{date}`). `kurs = NULL` means "rate unknown" and is surfaced in the UI; never default it to 1.
3. `Porezi/FifoKalkulator` is pure (no DB) and unit-tested against the spreadsheet; `FifoService::preracunaj()` deletes and rebuilds the user's `poreski_lotovi` / `alokacije_lotova_prodaje`. Call it (or `PrimenaKurseva::primeni()`) after anything that changes transactions or rates.
4. `KapitalnaDobitIzvestaj` / `DividendeIzvestaj` compute the spreadsheet columns per `Period` (`sve`, `2026`, `2026-H1`). Sales whose quantity exceeds imported buys keep the spreadsheet behaviour (basis from available lots only) and are flagged via `nedostaje`.
5. `Obrasci/ObrazacPdf` renders `resources/views/obrasci/*.blade.php` with dompdf. The views are facsimiles of the official forms (A4 landscape, measurements in mm taken from the scans; PPDG-3R = 3 pages + Deo 4 repeated per 9 blocks, PP OPO = 1 page). Both PDFs hold only the form; the FIFO and dividend calculations belong in a separate report. Fonts are from `resources/fonts` (OFL), registered in `ObrazacPdf`: Liberation Serif for PPDG-3R (same metrics as Times on the scan) and Carlito for PP OPO (same metrics as Calibri; the official PP OPO is an Excel sheet printed at 91.5 %: text 7.32 pt). PP OPO boxes are drawn with absolutely positioned lines to the measured geometry (`_kucice_opo`), because Carlito's `|`/`_` glyphs differ from Calibri's. dompdf quirks: no flexbox; `height` on `<tr>` is ignored (set it on a cell); boxes (`_kucice`) and bracket fields (`_polje`) are small nested tables, not inline-blocks; grid borders use child selectors so they don't leak into nested tables; `$s()`/`$v()` subtract padding and border from edge-to-edge sizes. `Obrasci/RasporedDela4` (pure, unit-tested) lays sales into Deo 4 blocks of 3 acquisition rows: a sale with 4+ lots continues in the next block with an empty redni broj. Form codes (vrsta prijave, šifra vrste prihoda, …) are defaults in `config/porezi.php` and are **unverified** — the UI tells users to check them.
6. XML for the ePorezi portal ("XML unos"; there is no API): `IzvozController::ppdg3rXml` / `ppOpoXml` (routes `izvoz.ppdg-3r.xml`, `izvoz.pp-opo.xml`) use `Obrasci/Ppdg3rXml` and `Obrasci/PpOpoXml` (pure, unit-tested), written through `Obrasci/Xml/PrijavaXml` (`ns1:` prefix, namespace `http://pid.purs.gov.rs`, amounts via `Decimal::zaXml()`). PP OPO follows the **official XSD** `resources/xsd/PPOPO-Prijava.xsd` (PURS, kept unmodified) and every download is validated against it (`PpOpoXml::proveri()`); amounts are rounded before `PorezZaUplatu = max(0, obračunati − plaćeni)`, and 2.8 is alpha-2 there (XSD v1.0.2), unlike the PDF. PPDG-3R has **no published schema**: its structure comes from tools whose files the portal accepts — Deo 4 as ppdg3r.rs (one `PodaciOPrenosuHOVInvesticionihJed` per sale with one `<Sticanje>` per FIFO lot, like the PDF), element order inside `<Sticanje>` and `IsplataUDelovima` as ibkr-porez; totals (Deo 5–6), attachments and fields 2.9/2.10 are left to the portal. Both refuse to generate (redirect back with an `xml` error) when data is incomplete: no sales in the half-year, a sale without a rate or with missing buys (`Ppdg3rXml::prepreke()`), a dividend without a rate, or a PP OPO that fails the XSD.

All money math uses `BcMath\Number` via `App\Support\Decimal` (`Decimal::format()` gives Serbian `1.519,96`). Decimal columns are deliberately not cast on models; use `$model->decimal('kolona')`. Every query on per-user tables is scoped by `korisnik_id`.

## Auth

- The auth model is `App\Models\Korisnik` (table `korisnici`), set in `config/auth.php`. The stock `User` model, factory and `users` migration are unused leftovers.
- The password column is `lozinka_hash`, wired through `protected $authPasswordName` plus a `hashed` cast. So `Auth::attempt(['email' => …, 'password' => …])` works unchanged; assign the plain password to `lozinka_hash` and the cast hashes it.
- Email verification is custom (not Laravel's `MustVerifyEmail`). `App\Services\VerifikacijaEmailaService` issues a hashed 6-digit code in `verifikacioni_kodovi` (15 min, max 5 attempts, one active code per user). It sets `korisnici.email_verifikovan_at` on success.
- Routes behind the `verifikovan` middleware alias (`App\Http\Middleware\EmailVerifikovan`, registered in `bootstrap/app.php`) require a verified email. Unverified users are sent to `/verifikacija`.
- The `obaveznik` alias (`App\Http\Middleware\PoreskiObaveznikPopunjen`) sits on every knjiga route except `/poreski-obaveznik`: until `PoreskiObaveznik::jePopunjen()` holds (`OBAVEZNA_POLJA`: only 2.1 tip, 2.3 ime i prezime, the municipality, 2.7 email and 2.9 (for every tip, pre-filled with Srbija for residents); the sensitive 2.2 JMBG/PIB, 2.4 prebivalište (PDF only), 2.5 adresa and 2.6 telefon (both omitted from the XMLs when empty; `minOccurs="0"` in the PP OPO XSD), 2.8 JMBG podnosioca, `tekuci_racun` and `broj_pasosa`, and 2.10, are optional: the PDF leaves them blank, and both XML exports refuse while `PoreskiObaveznik::nedostajeZaXml()` (2.2, 2.8) is non-empty), or until `Korisnik::prihvatioUslove()` holds (`uslovi_verzija` equals `config('pravno.verzija')`; the checkbox `prihvatam_uslove` on that form records it, and bumping the version makes everyone accept again once its `vazi_od` date (Europe/Belgrade) has passed; until then the previously accepted version still counts, see `App\Support\Pravno`), the user is sent to that tab, so the first login lands there. DB columns stay nullable; `PoreskiObaveznikRequest` enforces the rules. 2.9 is an `<input list>` over `config/drzave.php` (ISO alpha-2 => Serbian name), shown as "Srbija (RS)"; `App\Support\Drzave::oznaka()` turns the input back into the code that is stored. The municipality (`opstina_sifra`) works the same way: `<input list>` over `config/opstine.php` (treasury codes from Prilog 3 of the Pravilnik o uslovima i načinu vođenja računa za uplatu javnih prihoda, as the PP OPO rulebook prescribes), shown as "Grad Novi Sad (223)", `App\Support\Opstine::sifra()` stores the code. PP OPO 2.8 prints the ISO alpha-3 code (`config/drzave_alfa3.php`, `Drzave::alfa3()`: RS → SRB). On the PDF, 2.9 is the official full name in Cyrillic (`Drzave::zaObrazac()`: `config/drzave_zvanicno.php`, e.g. "Republika Srbija", "Savezna Republika Nemačka", falling back to the short name for states whose official name is the same and for territories, transliterated by `App\Support\Cirilica`). `tekuci_racun` is entered as `265-0000000360051-46`, the short `265-360051-46` (party padded with zeros) or 18 digits, stored as 18 digits and checked with MOD 97 (`App\Support\TekuciRacun`); PP OPO 3.2 (PDF) and `TekuciRacun` (XML) print it only when 3.1 is 1 (isplata na račun). Spell it "obaveznik" in code and Latin UI (not "obveznik").
- Password reset is custom too (not Laravel's `Password` broker). `App\Services\ResetLozinkeService` stores a sha256 of a random link token in `tokeni_reset_lozinke` (15 min, single use, one active per user) and never reveals whether an email is registered. A successful reset also marks the email verified and rotates `remember_token`.
- Google login (`laravel/socialite`, `GooglePrijavaController`, routes `prijava.google` / `prijava.google.povratak`, button `<x-google-dugme>` on `/prijava` only) is an extra way into the same `korisnici` row, not a separate account type. `GooglePrijavaService::korisnikZa()` matches by `google_id` (Google `sub`), then by email, else creates a user with an automatic `korisnicko_ime` (email local part, suffixed via `PredloziKorisnickogImenaService` when taken) and a random password; a newly created account is then sent once to `/nalog/korisnicko-ime` (session key `NalogController::IZBOR_IMENA`) to keep or change that name. The name can be changed later in Moj nalog (`PUT nalog.korisnicko-ime`, `KorisnickoImeRequest`, same rules and free-name suggestions as registration via `PredlaziSlobodnaImena`). TOTP 2FA is only a disabled "Uskoro" placeholder in Moj nalog. It requires Google's `email_verified`. Linking to an unverified local account replaces its password and `remember_token` (pre-hijacking). Fallback when OAuth is down: the user sets a password through the normal reset flow. Credentials: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` in `.env`.
- Insider feedback widget: `korisnici.is_insajder` (default 0, not fillable, `Korisnik::jeInsajder()`; the user opts in and out in Moj nalog, `PUT nalog.insajder`) shows `layouts/_podrska.blade.php` (floating button + Bootstrap modal, `resources/js/podrska.ts` sends it with `fetch`) to verified insiders. `POST /podrska` (`podrska.posalji`, middleware `insajder` → 404 for everyone else, `throttle:podrska` = 5 per 10 min and 10 per day per user, defined in `AppServiceProvider` because support mail shares the Brevo daily quota with verification codes, `PodrskaRequest`: limits are its constants and the widget reads them from `data-maks-*`). `PodrskaService::primi()` stores the message and its attachments (disk `local`, `podrska/{poruka_id}/{uuid}.{ext}`, extension from content) **before** sending `PodrskaMail` to `config('podrska.email')` (`PODRSKA_EMAIL`, a Zoho Mail inbox); a failed send leaves `poslato_at = NULL` for `php artisan podrska:posalji-neposlate`. From stays `MAIL_FROM_ADDRESS` (the Brevo-verified domain, so SPF/DKIM/DMARC pass) and Reply-To is the user. Messages live as long as the account; `BrisanjeNalogaService` deletes the rows and the attachment directories.
- Satisfaction prompt (insiders only): `layouts/_zadovoljstvo.blade.php` is rendered in `layouts/knjiga` only while `Korisnik::trebaPitatiZadovoljstvo()` holds (insider, verified, `zadovoljstvo_od` passed; NULL = "Ne pitaj više") and stays hidden until a button with `data-izvoz-obrasca` (PPDG-3R / PP OPO, PDF / XML) is clicked (`resources/js/zadovoljstvo.ts`, once per page load; a failed export reloads the page, so the card never shows). `POST zadovoljstvo.sacuvaj` stores a row in `ocene_zadovoljstva` (1–5, comment, `povod` from `OcenaZadovoljstva::POVODI`) and moves `zadovoljstvo_od` by `config('podrska.zadovoljstvo.*')` (90 days after an answer, 7 after "Ne sada"). `php artisan zadovoljstvo:izvestaj {--period=prosli-mesec} {--mejl}` (`ZadovoljstvoIzvestaj`, months in Europe/Belgrade) prints or mails the stats; it is scheduled monthly in `routes/console.php`, which needs `schedule:run` in the server's cron.
- `MAIL_MAILER=log`, so verification codes and reset links appear in `storage/logs/laravel*.log` (daily logs, `LOG_DAILY_DAYS=14`, the retention stated in the privacy policy).
- Privacy: `pib`, `jmbg_podnosioca`, `tekuci_racun` and `broj_pasosa` have the `encrypted` cast (APP_KEY; losing it loses that data), so never filter or sort on them in SQL; unit tests that build `PoreskiObaveznik` set `PoreskiObaveznik::encryptUsing()`. Public routes `/` (landing for guests, `JavneStraneController`), `/politika-privatnosti`, `/uslovi-koriscenja` (`resources/views/pravno/*`, controller identity, processors and retention from `config/pravno.php`; keep the text in sync when adding a third-party service). `/nalog` (`NalogController`, `verifikovan` but not `obaveznik`): JSON export and **hard** deletion through `BrisanjeNalogaService` (explicit delete of every per-user table plus sessions, then one anonymous `obrisani_nalozi` row; never keep per-user rows "soft-deleted"). New per-user tables must be added to `BrisanjeNalogaService::TABELE` and `izvoz()`. Changing the terms: bump `pravno.verzija`, set `vazi_od` ≥ 15 days ahead, fill `pravno.izmene`, deploy, then `php artisan pravno:obavesti` (`--proba` counts only, `--limit` for the SMTP daily cap; resumable via `uslovi_obavesten_verzija`). Silence is not acceptance (ZOO čl. 42), so acceptance stays an explicit checkbox.
- Validation messages come from `lang/sr/validation.php` (`APP_LOCALE=sr`). It covers only the rules in use, so add messages there when you use a new rule.

## Frontend

Blade + Bootstrap 5 + TypeScript (Tailwind was removed). The layout is `resources/views/layouts/app.blade.php` (navbar user dropdown with nalog, legal pages and odjava; footer with legal links), with `@yield('naslov')` for the title and `@yield('sadrzaj')` for the body. The entry point is `resources/js/app.ts`. Dashboard pages extend `layouts/knjiga.blade.php` (tabs, `@yield('knjiga')`). Design tokens (paper/ink/stamp-blue) are CSS variables at the top of `resources/css/app.css`; `<x-kucice :iznos>` renders the amount due in tax-form boxes. Page behaviour is attached through `data-*` attributes: `data-toggle-lozinka`, `data-poklapa-se-sa`, `data-kod-unos`, `data-odbrojavanje` (`resources/js/auth.ts`) and `data-auto-submit` (with a `<noscript>` submit button as the no-JS fallback), `data-potvrda`, `data-slanje` (+ `data-slanje-napomena`: spinner and a disabled button while a long POST such as import + NBS rate fetch runs), `data-lista-fajlova`, `data-tip-obaveznika` + `data-prikazi-za-tip="4"` (shows and enables fields per tip obaveznika, e.g. 2.10) (`resources/js/dashboard.ts`). Feature tests that render views need `$this->withoutVite()`.

### Tables (search and sort)

Every data table goes through `App\Support\Tabela\Tabela` + `<x-tabela>`. Search and sort run in SQL; the browser only follows links. A table is defined in `app/Tabele/*Tabela.php` as a list of `Kolona` (`tekst`, `ceo`, `decimalni`, `datum`, `enumeracija`, `akcija`), each with an SQL `izraz`. Computed money columns repeat the PHP formulas as SQL expressions; `SqlIzraz` inlines only code constants. The controller calls `$tabela->primeni($upit)`. Report pages compute rows and the **totals over the whole period** in PHP, and use `$tabela->izaberi()` only to filter and order the rows shown, so search never changes the tax due. URL state is `?q=…&sort=kolona:asc,kolona2:desc&vise=1`. Unknown keys are dropped, and `urlReseta()` keeps other params such as `period`. The search is OR across columns: text uses LIKE (`!` is the escape character), decimals match the *displayed* value as a prefix (`1.519,9` or `1519.9`), dates accept `15.03.2026` / `03.2026` / `2026` in Europe/Belgrade time, and enums match by label. The "Sortiranje po više kolona" switch (`vise=1`, no JS) makes a header click add its column to the sort instead of replacing it. Shift+click is deliberately not used, because browsers open the link in a new window. `initTabele` (`resources/js/dashboard.ts`) runs live search (from 2 characters, skipping incomplete numbers such as `2.`) and intercepts same-page table links (sort, ×, reset, switch, pagination). It fetches the page and swaps only the `[data-tabela-osvezi]` parts of `[data-tabela]`, with no reload. Clicks use `pushState` (Back works), typing uses `replaceState`. When you add a part of the component that changes with the table state, mark it with `data-tabela-osvezi="<name>"`.
